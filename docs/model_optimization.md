# 流式 TCN 模型优化说明

## 1. 文档目的

本文说明气体传感器响应加速与补偿模型从初始不可用状态优化到合成部署候选的过程，
涵盖问题诊断、模型结构、特征、损失函数、训练数据对齐、学习率策略、实验结果和
适用边界。

最终模型面向以下任务：同一支已标定 PdCu 氢气传感器每次接收一个采样点，在不使用
未来数据的前提下完成响应检测，并在检测后累计 15 秒数据，输出一个标准气体浓度等级。

## 2. 优化目标与最终结果

最初使用新版有状态合成数据训练时，验证 MAPE 达到 56.925%，完整回放 MAPE 为
54.732%。主要问题不是单纯的网络容量不足，而是数据不可辨识、训练与部署窗口不一致、
输出参数化不合适，以及短脉冲样本被训练集错误排除。

模型选择使用检测对齐验证集，并在开发测试完成后另外生成了一个未参与任何工程决策的
确认集。两个口径必须分开报告。

验证集结果：

| 指标 | 结果 |
| --- | ---: |
| 场景数 | 320 |
| 最佳等级投影 MAPE | **8.15%** |

全新确认集（`seed=8028`）的完整部署回放结果：

| 指标 | 结果 |
| --- | ---: |
| 测试场景/事件数 | 320/320 |
| 漏检事件 | 0 |
| 平均检测延迟 | 3.140 秒 |
| 最终 MAE | 67.467 ppm |
| 完整部署回放 MAPE | **9.872%** |

最终 checkpoint 为 `checkpoints/stream_v5_deployment_rocm72.pt`。

## 3. 原始方案的问题诊断

### 3.1 不可观测的器件参数造成不可辨识性

早期合成器在每个场景中独立随机化最大响应、Langmuir 系数和响应时间常数。输入只包含
一次气体暴露，却没有设备编号或单独的标定序列。此时相同电压曲线可能对应“低灵敏度、
高浓度”或“高灵敏度、低浓度”，模型无法仅通过增加参数量消除这种歧义。

v5 将任务重新限定为同一支已标定传感器和同一套气路的重复实验。器件级参数只保留
短期重复性误差，同时继续保留气室混合、双时间常数、温湿度变化、基线漂移、相关噪声、
尖峰和 ADC 量化。跨器件泛化不再被隐式假定；如果需要跨器件部署，必须提供每台设备的
标定数据或设备条件特征。

### 3.2 训练窗口与部署窗口错位

原训练流程从气体事件真值起点开始截取窗口，并随机增加 0～6 秒偏移；部署流程则从
`ResponseDetector` 实际越过阈值的时刻开始计时。慢响应传感器中，未知的几秒偏移会和
浓度幅值相互混淆，造成明显的训练—部署分布差异。

现在训练集构造过程直接复用部署侧的 `BaselineEstimator` 和 `ResponseDetector`：

1. 仅使用历史电压完成清洁空气基线标定；
2. 逐点运行响应检测器；
3. 在检测器实际触发时冻结可观测基线；
4. 从触发点截取 15 秒因果窗口；
5. 使用事件真值只提供训练标签，不参与检测触发。

这一修改使训练、验证和完整回放使用相同的窗口起点语义。

### 3.3 短脉冲训练缺失

生成器包含约 12% 的短脉冲。旧数据集要求“检测后阀门仍持续开启至少 15 秒”，因此
这些样本没有进入训练；但部署状态机在阀门关闭后仍可能处于缓慢恢复状态，并会继续收满
15 秒后输出结果。这一缺口使完整回放 MAPE 停留在 11.536%。

修复后，训练窗口只要求场景剩余长度不少于 15 秒，不再要求阀门持续开启。训练/验证
窗口数由 1388/281 增加到 1598/320，覆盖了短脉冲及其恢复段。低学习率微调后，
开发测试回放 MAPE 降至 9.680%，随后全新确认集回放 MAPE 为 9.872%。

## 4. 输入特征优化

模型输入保持为 8 个因果通道，形状为 `(B, 8, L)`：

| 通道 | 含义 |
| ---: | --- |
| 1 | 相对冻结基线的归一化电压 |
| 2 | 原始电压导数 |
| 3 | 从检测时刻开始的响应累计均值 |
| 4 | 归一化温度 |
| 5 | 归一化湿度 |
| 6 | 归一化响应持续时间 |
| 7 | 因果平滑斜率 |
| 8 | 弱稳态响应外推 |

平滑斜率由原来的 0.5 秒移动平均和 0.5 秒差分改为 2 秒移动平均和 2 秒差分，并根据
采样率动态计算窗口样本数。这样可以降低毫伏级白噪声被 `tau * dy/dt` 放大的问题。

弱稳态先验使用：

```text
response_steady ≈ response_smoothed + 30 s × slope_smoothed
```

该特征不直接反演浓度，也不读取真实基线或未来样本。TCN 可以根据完整响应曲线决定使用、
修正或忽略它。批量训练和逐点部署都调用同一套特征公式，并由回归测试保护两者的一致性。

## 5. 模型结构优化

### 5.1 因果 TCN 主干

TCN 主干由 6 个因果残差块组成：

```text
输入通道：8
隐藏通道：32 → 64 → 96 → 96 → 64 → 32
卷积核：15
膨胀率：1、2、4、8、16、32
每个残差块：两层因果卷积 + ReLU + Dropout + 残差连接
Dropout：0.10
```

每层卷积使用 `weight_norm`，使卷积核方向和幅值分别优化。网络不使用 BatchNorm 或任何
跨时间统计的归一化层，因此时刻 `t` 的预测只依赖不晚于 `t` 的输入。

模型感受野为 1765 个采样点，大于 100 Hz 采样下 15 秒窗口的 1500 个点，最终输出能够
覆盖完整响应历史。

### 5.2 浅层校准支路

仅靠深层 TCN 学习响应动力学和标定映射，早期训练容易停在接近中位浓度的常数预测。
因此增加一条浅层校准支路：

```text
(B, 8, L) → 1×1 Conv(8→16) → SiLU → 1×1 Conv(16→1)
```

浅层支路直接利用累计均值、温湿度和稳态代理等当前时刻特征；深层 TCN 负责延迟、快慢
动态和历史形状。两条支路的原始输出相加后进入浓度输出层。浅层支路最后一层采用零初始化，
因此加入时不会立即改变原 TCN 的初始预测。

### 5.3 可微 Langmuir 输出层

直接使用 `sigmoid × 1200 ppm` 容易在边界附近饱和；无上界 Softplus 输出虽然避免了硬
截断，但需要网络自行学习完整的传感器饱和曲线。最终模型让网络预测 Langmuir 占据率：

```text
s = sigmoid(z)
sqrt(c) = s / (K × (1 - s))
c = [s / (K × (1 - s))]²
```

其中 `K=0.045`，`z` 是深层和浅层支路相加后的原始输出。训练期间该变换连续可微。
该变换只保证网络标量 `z` 到浓度 `c` 的映射单调；TCN 输入到 `z` 的映射本身没有
单调约束。输出头偏置初始化为约 600 ppm 对应的占据率，避免初始化落入极低浓度区域。

### 5.4 标准气体等级投影

当前合成实验只使用以下七个标准气体等级：

```text
100、200、400、600、800、1000、1200 ppm
```

训练时模型保持连续输出，以保留梯度；切换到 `eval()` 或部署状态后，连续结果投影到最近的
标定等级。短脉冲修复前，长事件验证子集上的连续回归 MAPE 为 12.45%，同一 checkpoint
进行等级投影后为 8.57%。最终短脉冲微调阶段的 checkpoint 选择直接使用等级投影后的
验证 MAPE，最佳值为 8.15%。

该策略适用于标准气体等级识别，不代表模型能以相同精度预测任意连续浓度。如果部署需要
连续测量，应关闭 `quantize_in_eval`，使用覆盖连续浓度的实测标定集重新训练，并单独报告
连续输出指标。

## 6. 训练过程优化

### 6.1 对数浓度均方损失

早期相对 Huber 损失在误差较大时近似 L1。对于分布在多个浓度等级的数据，模型接近中位
浓度时，不同批次梯度容易相互抵消并产生振荡。最终训练使用对数浓度均方误差：

```text
e(t) = log(max(prediction(t), 1)) - log(max(target, 1))
```

只重点监督窗口末端：

```text
loss = mean(e², 最后 3 秒) + 2 × mean(e², 最终时刻)
```

对数误差在小误差区间近似相对误差，同时让低浓度和高浓度在相近的相对尺度上优化。
平方项为远离中位数的浓度等级提供比 L1 更强的纠偏梯度。

### 6.2 优化器和稳定性措施

训练采用：

- AdamW，权重衰减 `1e-4`；
- 梯度范数裁剪 `max_norm=1.0`；
- 固定随机种子；
- 每轮验证并立即保存验证 MAPE 最佳的 checkpoint；
- 训练、验证、测试使用相互独立的随机种子和文件。

### 6.3 Warmup 与余弦退火

学习率调度由线性 warmup 和余弦退火组成：

1. warmup 从峰值学习率的 10% 开始；
2. 在指定 warmup 轮数内升至峰值；
3. 随后余弦下降至最小学习率。

正式训练分为两阶段：

| 阶段 | 数据窗口 | 轮数 | 峰值学习率 | 最低学习率 |
| --- | --- | ---: | ---: | ---: |
| 历史基础训练 | 当时仅含检测后仍通气满 15 秒的窗口 | 50 | `1e-4` | `2e-6` |
| 部署对齐微调 | 修复构造器后包含全部短脉冲窗口 | 30 | `3e-5` | `1e-6` |

第二阶段从第一阶段最佳 checkpoint 热启动，但使用新的优化器状态，并在同一个验证 NPZ
经过修复后的窗口构造器得到的 320 个检测窗口上重新选择最佳模型。两阶段窗口差异来自
开发过程中的数据集构造代码修复，而不是不同 NPZ 文件或命令行开关；因此当前代码不能
逐字复现“先排除、再加入短脉冲”的历史过程。当前代码从第一阶段开始就会正确包含短脉冲。

## 7. 实验演进

| 实验 | 主要变化 | 验证 MAPE | 完整回放 MAPE | 结论 |
| --- | --- | ---: | ---: | --- |
| 有状态 v2 基线 | 跨虚拟器件大范围随机参数 | 56.925% | 54.732% | 输入无法辨识器件灵敏度 |
| v3 小样本 | Softplus 输出、对数 Huber、同批次参数 | 22.85% | 未作为最终测试 | 数值塌缩消失，但仍有动态歧义 |
| v4 正式训练 | 检测对齐、浅层校准支路 | 12.68% | 未作为最终模型 | 窗口对齐显著改善结果 |
| v4 对数均方微调 | 对数均方替代 Huber | 12.50% | 未作为最终模型 | 损失改善有限，接近平台 |
| v5 Langmuir 连续模型 | 单调物理输出层，长事件验证子集 | 12.45%（连续） | 未报告 | 连续回归仍在平台区 |
| v5 等级投影 | 对同一模型启用标准等级投影 | 8.57%（投影） | 11.536% | 短脉冲仍未进入训练 |
| v5 部署对齐微调 | 纳入短脉冲恢复窗口 | **8.15%（投影）** | **9.680%（开发测试）** | 达到合成标准等级目标 |
| v5 最终确认 | 固定模型，仅更换全新随机种子 | 不适用 | **9.872%（确认集）** | 未参与模型或流程选择 |

这些跨版本数字同时改变了任务定义、数据分布、模型和训练过程，不是严格的单变量消融，
尤其不能把 56.925% 到 9.872% 全部归因于网络结构。最主要的前提变化是把不可辨识的
跨器件任务收紧为同一已标定传感器。表格用于记录工程演进，不用于估计各改动的独立贡献。

第一次开发测试得到 11.536% 后，结果被用于定位短脉冲训练缺口，因此之后在同一个
`test_v5.npz` 上得到的 9.680% 只能视为开发测试，不能再称为未触碰测试。最终模型固定后，
另外用 `seed=8028` 生成 `holdout_v5.npz`，只执行一次确认回放，得到 9.872%。

## 8. 开发测试中的事件对齐指标与部署指标

最终模型在开发测试集上的事件真值对齐窗口结果为：

| 时间点 | MAPE |
| ---: | ---: |
| 5 秒 | 132.521% |
| 10 秒 | 42.840% |
| 15 秒 | 14.191% |

事件对齐窗口从阀门命令发生时开始，其中包含气路纯延迟、气室混合和检测器尚未触发的阶段。
部署回放则从检测器实际触发后累计 15 秒，和训练窗口语义一致，因此得到 9.680%。

所以准确的性能表述是：

> 模型在因果检测器触发后等待 15 秒，并输出七个标准气体等级时，合成回放
> MAPE 在开发测试集为 9.680%，在未参与决策的确认集为 9.872%。

不能表述为“从阀门开启后任意 15 秒窗口均低于 10%”。

## 10. 当前等价工作流示例

以下命令展示当前代码推荐的训练流程，但不能重新生成获得 9.872% 的历史 checkpoint：
该 checkpoint 的基础阶段使用修复前的数据集构造器排除了短脉冲，随后才使用修复后的
构造器微调；当前代码从基础阶段开始就会包含短脉冲。要严格复核本文结果，应直接使用
下方 SHA-256 标识的 checkpoint 和确认集，而不是覆盖它们重新训练。

生成相互独立的数据集和最终确认集：

```bash
uv run python main.py generate --output data/train_v5.npz --count 1600 --seed 7026
uv run python main.py generate --output data/val_v5.npz --count 320 --seed 7027
uv run python main.py generate --output data/test_v5.npz --count 320 --seed 7028
uv run python main.py generate --output data/holdout_v5.npz --count 320 --seed 8028
```

当前代码的基础训练会从一开始就包含常规和短脉冲检测窗口：

```bash
uv run python main.py train \
  --data data/train_v5.npz \
  --val-data data/val_v5.npz \
  --checkpoint checkpoints/stream_v5_langmuir_rocm72.pt \
  --epochs 50 --batch-size 32 --lr 1e-4 \
  --warmup-epochs 2 --min-lr 2e-6 --device cuda
```

可选的低学习率部署对齐微调：

```bash
uv run python main.py train \
  --data data/train_v5.npz \
  --val-data data/val_v5.npz \
  --checkpoint checkpoints/stream_v5_deployment_rocm72.pt \
  --epochs 30 --batch-size 32 --lr 3e-5 \
  --warmup-epochs 1 --min-lr 1e-6 --device cuda \
  --resume checkpoints/stream_v5_langmuir_rocm72.pt
```

全新确认集的完整部署回放：

```bash
uv run python main.py replay \
  --data data/holdout_v5.npz \
  --checkpoint checkpoints/stream_v5_deployment_rocm72.pt \
  --device cuda
```

以上示例依赖当前代码默认值：采样率 100 Hz、响应窗口 15 秒、清洁空气标定 20 秒、
每个场景 180 秒且默认一个事件；训练函数内部执行 `torch.manual_seed(0)`。Langmuir
系数 `K=0.045`、七个浓度等级、`feature_version=weak_prior_v4` 和
`model_version=context_langmuir_logmse_v4` 均写入 checkpoint。示例用于后续重新训练，
其结果需要新的、未参与选择的确认集重新验证，不能沿用本文 9.872%。

## 11. 回放指标定义

- 检测延迟以阀门命令事件起点为零点，计算检测器触发时刻与事件起点之差；
- 每个匹配事件只记录一次锁定浓度；
- MAE 和 MAPE 是对成功匹配事件最终锁定值的事件级宏平均；
- 本次确认集 320 个事件全部检出，因此 MAPE 覆盖全部事件；
- 当前 `replay` 汇总未单独报告未匹配到真值事件的额外检测，因而不能把“0 漏检”等同于
  已证明“0 误报”。部署前还应增加误报率和纯空气长时间回放指标。

## 13. 适用边界与后续工作

当前结果仍有以下边界：

1. 9.872% 来自合成确认集，不代表真实 PdCu 传感器精度；
2. 结果面向同一支已标定传感器，不代表跨器件泛化；
3. 低于 10% 的结果依赖七个标准浓度等级投影；
4. 任意连续浓度、不同气路、不同采样率和长期老化均需要重新验证；
5. 开发测试中从阀门命令起点计算的 15 秒 MAPE 仍为 14.191%；
6. 实际部署前应使用真实标定数据重新拟合 `langmuir_k`，并同时报告连续回归和等级投影结果。

下一步应优先采集同一设备多轮重复标定数据，包括不同温湿度、短脉冲、完整恢复和长期漂移；
然后保持测试集封存，重新训练并比较合成预训练、实测微调及纯实测训练三种方案。
